# 🌐 Internationalization (i18n) and localization (l10n)

Status: **plan accepted 2026-10-11 — Wave 0 in progress** (branch `i18n`). This file is the contract for every text a
learner reads in the app. It grows with each wave; the language courses' own architecture (core + facades) is
`docs/language-packs.md`.

## 1. Three languages that are never the same thing

| | What | Where it is stored | Default |
|---|---|---|---|
| **UI language** | the app's chrome: buttons, menus, settings, messages | `a:settings.lang` (account, synced, in backups; Arabic digits: `a:settings.numerals` = `arab` \| `latn`) | the device's language if supported, else `en` (asked once to confirm) |
| **Speaker language** | the language a course or pack is explained in | language courses: per course, `s:lang:<course>:settings.speaker` (changeable any time); subject packs: `subject.language`, chosen at creation (default `en`) | language courses: the UI language |
| **Learned languages** | what the language module teaches | `s:lang:<course>:settings.languages` | the course's languages |

The UI language never changes a pack's or course's content, and the other way round. Learned languages are open-ended
(Hebrew is learned, but is not a UI locale).

## 2. Decisions

| Topic | Decision |
|---|---|
| UI locales (BCP 47) | `en` (source, final fallback) · `el` · `ru` · `fr` · `ar-EG` · `de` · `hi` · `zh-Hans` · `zh-Hant` · `ja` · `it` · `es-ES` · `sq` · `pt-PT` |
| Fallback chains | `ar-EG → ar → en` · `es-ES → es → en` · `pt-PT → pt → en` · `zh-Hant → en` (never Simplified for a Traditional reader) · `zh-Hans → en` · every other `xx → en`. Missing key in production: the English text, logged once; never a raw key |
| Arabic | Modern Standard Arabic; digits Arabic-Indic (٠١٢٣, CLDR `arab`, the ar-EG default) — switchable to Latin in Settings (`numberingSystem: arab | latn`) |
| Address | el εσύ · ru ты (the current mixed ты/вы is unified) · fr tu · de du · it tu · es tú · pt tu (pt-PT) · sq ti · hi आप · ja です/ます · zh 你 · ar أنت (MSA, gender-neutral phrasing where possible) |
| Catalog format | **ARB** (Application Resource Bundle: JSON with ICU MessageFormat strings and `@key` metadata — description = the translator comment, placeholders, context). One file per component and locale: `i18n/<component>/<locale>.arb`; Claude's drafts in `i18n/<component>/drafts/<locale>.arb`. Weblate reads and writes ARB natively (plurals per CLDR, descriptions shown to translators, ICU checks) |
| Runtime | `intl-messageformat` (FormatJS, vendored in `engine/vendor/`) + `Intl.*`; `engine/i18n.js` keeps its API (`NoemaI18n.t(key, params)`) and loads the active locale's catalog lazily; only `en` is in the first load |
| Keys | semantic, dotted (`pick.what`, `tutor.ask`), never the English text; every key has an `@key.description` |
| Plurals and choices | ICU only: `{n, plural, one {# card} other {# cards}}`, `{gender, select, …}`. No `n === 1 ? … : …` and no string concatenation |
| TMS | **Weblate** (self-hosted later; temporarily elsewhere — §9). The repo is the single source of truth: only `i18n/*/en.arb` is edited in the repo; translations are edited only in Weblate, which pushes them back as Pull Requests (never to `main`). Claude's drafts are imported as *needs editing*. Translators accept a CLA covering commercial use |
| Flags | never a UI-language picker: the picker lists endonyms (Ελληνικά, Русский, العربية …) with the BCP 47 code. The language module's per-card flags stay as a content-language toggle, always with an accessible label (endonym + ISO code) |
| Fonts | self-hosted Noto (Arabic, Devanagari, SC, TC, JP; Hebrew for content) subset per script, `font-display: swap`, loaded only when the locale or the content needs the script |

## 5. How to write a translatable text (the rules every change follows)

### 5.1 Components, keys, files

| Component (`i18n/<c>/`) | Code | Key prefix |
|---|---|---|
| `core` | shared by `engine/src/*` (`t()`) and `engine/loader.js` (`tr()`) — the keys migrated from the old bundles | `pick.` `set.` `acc.` … (as they are) |
| `shell` | `engine/shell.js` (`L()`, prefix added by `L`) | `sh.` |
| `engine` | `engine/src/*.js` | `engine.` |
| `loader` | `engine/loader.js`, `react.js`, `convos.js`, `viewer.js`, `imglib.js`, `index.html` | `loader.` |
| `roadmaps` | `curmap.js`, `curriculum.js`, `curshare.js`, `curjobs.js`, `curimport.js`, `packgen.js`, `packcheck.js` | `roadmap.` |
| `characters` | `themes.js`, `art.js` | `char.` |
| `lang` | `engine/lang/*.js` (the language module's UI) | `lang.` |
| `langcore` | `engine/langcore.js` (exercise words and labels generated at run time) | `lc.` |
| `errors` | `cloud.js`, `srcfiles.js`, `claude.js`, `llm.js`, `cloud/img/proxy.mjs`, error codes of the backend | `err.` |
| `email` | `cloud/email/*` (Supabase auth e-mails) | `email.` |

* Keys are semantic and dotted: `engine.notif.empty`, `roadmap.step.markDone` — never the English text, never reused for a
  different meaning (the same English word in two places = two keys if a language could say them differently).
* Every English key has a description for translators: where it appears, what the placeholders are, length limits
  (`"@engine.notif.empty": {"description": "Notifications panel when there is nothing new. Short.", "placeholders": {…}}`).
* Keys built at run time (`'sh.dom_' + id`) are listed in `i18n/<c>/dynamic_keys.txt` (a key or `prefix*` per line).
* Only `en.arb` is written by hand. Claude's translations go to `drafts/<locale>.arb` (imported into Weblate as *needs
  editing*); `<locale>.arb` is written by Weblate only (and once by the migration of the old bundles).
* Generated, never edited: `engine/i18n/*.js` (`node tools/i18n/build.js`, run by `tools/build.py`).

### 5.2 In the code

```js
const T = (k, p) => window.NoemaI18n ? NoemaI18n.t(k, p) : k;          // per file (engine/src has t(), loader tr(), shell L())
toast('✅ ' + T('engine.saved', { title }));                             // a leading decorative emoji may stay outside
T('roadmap.steps', { n: steps.length })                                  // "{n, plural, one {# step} other {# steps}}"
NoemaI18n.fmt.date(ts) · fmt.number(x) · fmt.percent(r) · fmt.ago(ts) · fmt.list(names) · fmt.compare(a, b)
```

* **A whole sentence is one message.** No `'You have ' + n + ' cards'`, no sentence glued from pieces, no `n === 1 ? … : …`
  (ICU plural), no English word order in code. A bold part: a placeholder filled with an element (`rich()` in shell.js).
* **Plurals** `{n, plural, one {# card} other {# cards}}` (`#` prints the number in the locale's digits); a bare `{n}`
  is not number-formatted — write `{n, number}`. Choices: `{kind, select, pack {…} roadmap {…} other {…}}`.
* **Apostrophes**: write ’ (U+2019) in messages; an ASCII `'` before `{` `}` `#` starts ICU quoting (`check.js` refuses it).
* **Numbers, dates, lists, sorting** only through `NoemaI18n.fmt` (never `toLocaleString()` without the UI locale,
  never `a.localeCompare(b)` without it).
* **Not for learners → mark it**: `// i18n-ignore` on the line, `/* i18n-ignore-start */ … /* i18n-ignore-end */` around
  a block: prompts for the AI (approach 6: written in English, they *ask* for the learner's language), logs, test hooks,
  sample text in a learned language, CSS/SVG.
* **English stays word for word** what it was (the tests read it); a better English text is a separate, explicit change.
* **Errors**: a message a learner reads is translated where it is shown. The backend answers
  `{ error: { code: 'img.too_large', params: { max: 10 }, message: '<English, for old clients>' } }`; the app shows
  `T('err.' + code, params)` and falls back to `message` (§6).
* **RTL**: CSS logical properties (`margin-inline-start`, `inset-inline-end`, `text-align: start`); user and course text
  inside an RTL page gets `dir="auto"`; icons that point (← →) are mirrored with `:dir(rtl)`.

### 5.3 Checks (CI: `bash tests/run_e2e.sh` runs them)

* `node tools/i18n/check.js` — ICU syntax, placeholders equal to English, CLDR plural categories per locale (ru: one/few/
  many/other; ar: zero/one/two/few/many/other), keys not in English, keys missing in a locale that is on, apostrophes,
  descriptions; sensitive keys (`"x-sensitive": true`: legal, billing, safety) never shipped as drafts.
* `node tools/i18n/audit.js --diff main` — no new hard-coded learner text in the lines a change adds.
* `node tests/i18n.js` — runtime: chains, plurals in ru/ar/fr/ja, digits, pseudo-locales, missing keys, error codes.
