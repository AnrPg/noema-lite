# py-module@1 (docs/activities-dev/pyodide.md): response headers for the website.
# The integrator adds these lines to the _headers that tools/build.py build_site() writes (dist/site/_headers), and runs
# `python3 tools/fetch_pyodide.py` AFTER `python3 tools/build.py site` (build_site empties dist/site).
#
# Needed:
#   · Service-Worker-Allowed — the worker script lives in /engine/ but its scope is /vendor/pyodide/ (register() fails without it;
#     the app then falls back to its own cache, which works but is not the service worker of docs/adr/001 D7).
#   · immutable caching of the versioned folder (the path changes with every Pyodide version; the manifest is not versioned).
#   · application/wasm for the .wasm (the app reads bytes, so this is only for a direct fetch).
# Not needed by this design, kept for a direct load from a sandboxed frame (spike a: without them a direct load hangs silently):
#   · Access-Control-Allow-Origin: * and Cross-Origin-Resource-Policy: cross-origin.

/engine/pyodide-sw.js
  Service-Worker-Allowed: /vendor/
  Cache-Control: no-cache
  Content-Type: text/javascript; charset=utf-8
/vendor/pyodide/manifest.json
  Cache-Control: no-cache
  Access-Control-Allow-Origin: *
/vendor/pyodide/0.27.7/*
  Cache-Control: public, max-age=31536000, immutable
  Access-Control-Allow-Origin: *
  Cross-Origin-Resource-Policy: cross-origin
/vendor/pyodide/0.27.7/*.wasm
  Content-Type: application/wasm
/vendor/pywheels/*
  Cache-Control: public, max-age=31536000, immutable
  Access-Control-Allow-Origin: *
  Cross-Origin-Resource-Policy: cross-origin
