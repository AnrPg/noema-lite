# noema-lite — content specification (any subject)

This is the contract between the **study engine** (subject-agnostic) and a **subject pack**.
Claude follows it when ingesting new sources; `tools/validate.py` enforces it; `tools/build.py` packs it.

## Repository layout of one subject
```
library/subjects/<subject-id>/          (shared library)   or   accounts/<profile>/packs/<subject-id>/   (private)
├── subject.json      identity + settings (below)
├── sources.json      the sources (PDFs, links…) in chronological order; maps chapter & patch files to sources
├── sources/          the original files (PDFs…) — archived, never published to the website
├── chapters/chNN.json   one file per chapter (schema below)
├── patches/*.json    ADDITIVE updates from later sources (never edit a published chapter; append)
├── media/            pictures (svg/png/jpg/webp) + media.json registry — docs/VISUAL.md
├── coverage/*.md     coverage checklists (every heading/command/test question → section + exercise ids)
├── authoring/        scripts used to generate the content (provenance)
└── pack.js / pack.json   GENERATED by tools/build.py (do not edit)
```

## subject.json
```json
{ "id": "cell-biology", "title": "Cell Biology", "appTitle": "Cell Biology Quest", "emoji": "🧬",
  "group": "life-sciences",                   // one of library/groups.json
  "description": "One line for the picker.", "language": "en",   // language of the material (tutor replies in it)
  "features": { "math": false, "code": false },                  // math → KaTeX; code → code highlighting & 'write' tasks
  "hero": { "headline": "Master **Cell Biology**, one bite at a time.", "mantra": "The one-sentence mental model." },
  "searchExamples": "mitosis, ATP synthase, p53",
  "tutor": { "name": "Brick", "avatar": "🦉", "domain": "cell biology",
             "prior": "What the learner already knows for THIS subject.",
             "examples": "Concrete examples to use (e.g. a liver cell under stress).",
             "interviewer": "an examiner for a cell biology oral exam",
             "simulation": "an experiment with an unexpected result, a patient case…",
             "terminology": "\"ATP synthase\", \"G1/S checkpoint\"", "examinerRole": "cell biology examiner" } }
```
The learner's personal profile ("About me") lives in the account, not in the subject.

## sources.json
```json
{ "sources": [ { "id": "part1", "title": "…", "subtitle": "…", "pages": "1–402", "file": "sources/part1.pdf", "added": "YYYY-MM-DD", "emoji": "📘" } ],
  "chapters": { "ch01": "part1" }, "patches": { "ch11_links.json": "part2" } }
```
Every item inherits its chapter's source; patched-in items inherit the patch's source (or carry an explicit `"src"`).
This powers the in-app Sources menu, "✨ what's new" and source filtering.

## Pedagogy rules (non-negotiable)
1. **Coverage**: teach AND test every concept, number, caveat, trap, worked example and test question of the sources. Repeated material is taught once (best version). Every source exercise/test question becomes ≥1 exercise with its solution as the explanation.
2. **Diagnostic thinking first**: wherever the source describes failures, errors, anomalies, misconceptions, differential diagnoses or "first thing to check", build a `debug` playbook with an ordered `askYourself` list (first-person questions), an `ask` block in the section, ≥1 `scenario` and ≥1 `order` exercise. Long playbooks get a `mnemonic`.
3. **Pitfalls / exam traps** → callout (pitfall/exam/warn) + chapter `pitfalls` entry + ≥1 exercise tagged pitfall/exam.
4. **Co-location**: related concepts in the same section; comparisons side by side (`compare`/`table`); each exercise attached to its section; 2–4 `quick` exercises per section.
5. **ADHD-friendly**: 1–3 sentence paragraphs, concrete examples, analogies, one idea per block, `reveal` "think first" prompts.
6. **Accuracy**: faithful to the sources; correct clear errors (and say so in the coverage notes); no invented facts.
7. Diagrams redrawn cleanly (≤70 chars wide). Explanations teach (why right + why the tempting wrong answer is wrong). Every exercise type used several times per chapter.
8. **Visual learning (mandatory, docs/VISUAL.md)**: every chapter gets ≥ 1 `figure` block and **≥ 3 visual exercises of ≥ 2 visual types** (hotspot, sequence, reveal, drag, label, select, occlusion). Draw the source's structures, architectures, flows, timelines, maps or apparatus with `tools/svgkit.py` (regions come out aligned with the drawing). One good picture usually serves 3–4 exercises. Enforced when `subject.json` has `"authoring": {"minVisualPerChapter": 3}` (default for new subjects).

## Inline text format (all text fields)
`**bold**`, `*italic*`, `` `inline code` ``, and `\n` for a line break. No HTML.
Math (subjects with `features.math`): `$…$` inline, `$$…$$` display (KaTeX). Inside math write `\cdot` / `\times`, never a bare `*` (it would be read as italics).

```json
{
  "id": "ch05", "num": 5,
  "title": "Delta Lake Internals",               // short
  "subtitle": "How SQL commands become files + log commits",
  "emoji": "🔺",

  "mantra": "One sentence mental model for the whole chapter.",
  "objectives": ["You can explain …", "You can write …", "You can debug …"],     // 4–8
  "sections": [ Section ],          // 6–16 sections
  "debug": [ Playbook ],            // as many as the source supports (min 3)
  "pitfalls": [ {"title": "...", "text": "...", "fix": "..."} ],
  "flashcards": [ {"q": "...", "a": "...", "section": "ch05-s03"} ],   // 20–50, crisp
  "exercises": [ Exercise ]
}
```

## Section
```json
{ "id": "ch05-s03", "title": "Time Travel & RESTORE", "hook": "One line: why should I care?",
  "blocks": [ Block, ... ] }       // 5–20 blocks
```

## Blocks (`t` = type)
- `{"t":"p","text":"..."}`
- `{"t":"list","items":["...","..."],"ordered":false}`
- `{"t":"code","lang":"sql|python|bash|yaml|text","code":"multi\nline","caption":"optional"}`
- `{"t":"diagram","text":"ASCII art\nmulti-line","caption":"optional"}`
- `{"t":"table","head":["Axis","Options"],"rows":[["..",".."]],"caption":"optional"}`
- `{"t":"callout","kind":"key|pitfall|tip|exam|warn|analogy|debug|interview","title":"...","text":"..."}`
- `{"t":"compare","items":[{"title":"Classic","points":["..",".."]},{"title":"Serverless","points":[".."]}]}`  (2–3 items)
- `{"t":"flow","items":["READ","WRITE","VALIDATE","COMMIT"],"caption":"optional"}`   (a process chain, 2–9 short steps)
- `{"t":"reveal","label":"Think first: …?","text":"answer revealed on click"}`
- `{"t":"ask","title":"Ask yourself when … ","questions":["Am I …?","Did …?"]}`
- `{"t":"terms","items":[{"term":"Principal","def":"..."}]}`
- `{"t":"figure","media":"heart-frontal","caption":"optional"}` — an explorable picture (docs/VISUAL.md §4)

## Exercise — common fields
```json
{ "id": "ch05-e012", "type": "...", "section": "ch05-s03", "difficulty": 1, "tags": ["concept"],
  "quick": false, "q": "Prompt (inline format allowed)", "code": "optional code shown under the prompt",
  "explain": "Teaching explanation shown after answering." }
```
`tags` ⊂ {concept, syntax, pitfall, debug, exam, interview, calc, compare}.
IDs: `chNN-eNNN`, unique, sequential.

### Types (extra fields)
| type | fields | notes |
|---|---|---|
| `mcq` | `options:[str]`, `answer:int` or `answer:[int,...]` + `"multi":true`, optional `why:[str per option]` | 3–5 options, plausible distractors; `why` strongly encouraged |
| `tf` | `answer:true/false` | `q` is a statement. Great for myths & traps. |
| `odd` | `options:[4 str]`, `answer:int` | "Which one doesn't belong?" — explain the grouping |
| `order` | `items:[str]` in the CORRECT order | 3–8 items; engine shuffles |
| `match` | `pairs:[[left,right],...]` | 3–6 pairs, rights must be distinct |
| `bucket` | `buckets:[str]` (2–4), `items:[{"text":..,"bucket":idx}]` | 5–10 items |
| `cloze` | `text` with blanks `[[answer|alt answer|alt]]`, `"bank":[distractors]` optional, `"asCode":true` for code | With `bank` → learner taps chips into blanks; without → types. First variant is canonical. Answers compared case-insensitively, whitespace-trimmed. |
| `spotbug` | `lines:[str]` (code lines), `bugs:[line indexes, 0-based]`, `fix:"corrected code or text"` | learner clicks the buggy line(s) |
| `calc` | `answer:number`, `tolerance:number`, `unit:"tasks"` | numeric reasoning |
| `scenario` | `steps:[{"prompt":..,"code":opt,"options":[{"text":..,"ok":true/false,"fb":"feedback"}]}]` | debugging simulations: each step = "what do you check/do next?". 2–5 steps, exactly one ok per step, every option has `fb`. |
| `free` | `model:"model answer"`, `rubric:["key point",...]` | explain-in-your-own-words / interview answers. Graded by Gemini or self-check. |
| `write` | `solution:"code"`, `keywords:["merge into","when matched",...]`, `lang` | learner writes real syntax; local check = all keywords present (case-insensitive substring) |
| `img_hotspot` `img_sequence` `img_reveal` `img_drag` `img_label` `img_select` `img_occlusion` | `media` + regions/targets/answer… | **visual exercises — full schema in docs/VISUAL.md** |

## Debug playbook
```json
{ "id": "ch05-d01", "title": "MERGE fails: multiple source rows matched", "section": "ch05-s08",
  "symptom": "What the learner sees (error text / behaviour)",
  "askYourself": ["Question 1 I ask myself first?", "Question 2?", "..."],     // ordered, 3–9
  "steps": [ {"do": "Run DESCRIBE HISTORY …", "why": "…", "code": "optional"} ],
  "rootCauses": ["…"], "fix": "…", "mnemonic": "optional short memory hook" }
```

## Quantity guide
Roughly ≥ 5 exercises per section, every section has ≥ 2 quick ones. ≥ 3 visual exercises + ≥ 1 figure per chapter. Every exercise type appears ≥ 2× per chapter
(`mcq`, `tf` and `cloze` more). ≥ 30% of exercises tagged `pitfall`, `debug` or `exam`.
Be exhaustive rather than brief: depth and coverage beat polish.

## Also produce
`chNN.coverage.md`: a checklist of EVERY numbered heading / concept / command / test question in your page range →
the section id and exercise ids that cover it. Use it to self-audit before finishing; add anything missing.


## Additive updates (new sources for an existing subject)
* Never edit or delete published chapter files — progress and SRS schedules are keyed by section/exercise ids.
* New topics → new chapter files (next free `chNN`). Material for existing sections → a patch file in `patches/`:
```json
{"patches":[{"chapter":"ch02","section":"ch02-s05","appendBlocks":[…],"appendExercises":[…],"appendFlashcards":[…],"appendPitfalls":[…],"appendDebug":[…]}]}
```
  Patched exercise ids must not collide: reserve a range per patch file (e.g. `chNN-e7NN`). Databricks: `e6NN` = visual_v1, `e7NN`–`e9NN` = the links patches.
  Typical patch content: a `callout` (kind key/tip, title "Level-up → …") linking to the deeper new chapter, plus genuinely new nuances with an exercise each.
* Register the new source in `sources.json` (append; order = chronology) and map the new chapter/patch files to it.
* `python3 tools/build.py` validates the MERGED result; `python3 tools/db_sync.py` records the new version in the backup database.

## Validation
`python3 tools/validate.py FILE.json` (single chapter) — `python3 tools/build.py` (everything, merged with patches).
